# 技术选型流程与决策记录

## 当前状态

**尚未选型。** 当前没有确定的游戏引擎、渲染框架、编程语言、构建工具或依赖版本，不据此文档创建工程。

## 主 Agent 职责

1. 阅读[游戏需求记录](requirements.md)，明确会影响选型的玩法、平台、操作方式和性能约束。
2. 根据已确认需求筛选候选方案，核对官方文档、版本和许可证，区分事实与推测。
3. 按以下标准对比候选方案；确有必要时提出最小验证方案，说明验证范围与验收条件。
4. 记录推荐结论、理由、限制和验证结果；确认选型后再初始化实际开发工程。

## 评估标准

| 维度 | 需要核对的内容 |
| --- | --- |
| 玩法适配 | 场景、相机、输入、碰撞、物理、动画和 UI 能力 |
| 平台兼容 | 目标设备、浏览器及所需图形接口支持情况 |
| 性能与加载 | 在目标设备上的帧率、资源体积、内存和加载表现 |
| 开发体验 | 编辑器需求、调试、测试、资源工作流与构建方式 |
| 维护与成本 | 文档、维护状态、学习成本、许可证和商业使用约束 |
| 发布条件 | 静态托管或服务端需求，以及部署与运维成本 |

尚未确定的指标引用需求记录中的待确认项，不擅自填写数值或兼容承诺。
