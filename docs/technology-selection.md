# 原型技术选型

## V2 决策（2026-11-12，主 Agent）

用户已批准完全 Canvas 界面、随机记忆任务、更大的地图与粒子系统，目标设备明确为 iPad Air 4 横屏。本轮改用 **Babylon.js 9.35.0 + 官方 GUI 9.35.0 + Vite**，WebGL 2、固定斜俯视真 3D。GUI 与场景绘制于同一个可见 Canvas；HTML 只负责容器。选择引擎以复用 GUI、资源容器、相机、拾取和粒子能力，减少自行维护的网页交互代码。

所有有限版本资源在开始前完成加载、解析、音频解码与预热，游玩时不使用 CDN 或在线语音。依赖精确锁定，Babylon.js 为 Apache-2.0。目标稳定 30 FPS 为实现目标，未经 iPad Air 4 真机测量不得声称达标。详细接口见 [V2 实施合同](v2-contract.md)。以下保留 V1 决策历史。

## 决策（2026-11-12，主 Agent）

根据已确认的 iPad 横屏、固定斜俯视、点击驾驶和低多边形玩具风格，选用 **Three.js 0.180.0 + 原生 JavaScript/HTML/CSS + Vite 8.3.8**。用户本轮已要求生成可运行代码；选型完成后建立本原型。

| 方案 | 评估与取舍 |
| --- | --- |
| Three.js + 正交相机 | 适合少量程序几何、真实光照、固定镜头；可自主控制触屏界面与体积。采用。 |
| Canvas 2D / SVG | 轻便，但低多边形物体、深度遮挡、转向和统一光照需额外手工实现。 |
| 完整游戏引擎导出网页 | 当前玩法无需编辑器、复杂物理或大型资源工作流；原型阶段引入成本较高。后续复杂化时再评估。 |

## 依据与约束

- 正交相机不随深度缩放，适合固定斜俯视沙盘：[官方文档](https://threejs.org/docs/#api/en/cameras/OrthographicCamera)。
- [WebGLRenderer](https://threejs.org/docs/#api/en/renderers/WebGLRenderer)：本版本需要 WebGL 2，启动失败须给出明确回退提示，不能白屏。
- [Vite](https://vite.dev/guide/)：用于本地开发与静态构建。npm 元数据核对版本和 Node 要求（^20.19.0 或 >=22.12.0），当前 Node 24.22.1 满足。
- Three.js 与 Vite 均为 MIT，具体版本锁定在 package.json / package-lock.json。
- 无额外 UI 框架或物理引擎。采用 Three.js GLTFLoader 加载随项目分发的 Kenney 小车；Three.js、模型、纹理与音效均本地打包，运行不依赖第三方 CDN。
- 代码以 Safari 15 为构建语法目标；这不代表已在 Safari 15/iPad 真机验证。
- 像素比上限 1.5，固定场景，适度阴影。云端软件渲染仅验证功能，不作真机性能结论。

## 模块接口

- `src/game.js`：任务状态、道路寻路、贴纸数据；纯逻辑可独立测试。
- `src/town.js`：正交 3D 场景、点击拾取、自动驾驶、暂停与投影位置。
- `src/main.js` / `src/style.css`：触控界面、声音、保存、任务提示及整合。
- 坐标为 x/z 平面，y 向上，网格节点 x,z∈{-5,0,5}；汽车沿网格移动，不斜穿建筑。
- 主 Agent 负责集成和共享配置，子 Agent 分别独占场景与纯逻辑文件。

## 验证状态

实现后的构建、逻辑测试、浏览器交互和环境限制记录在 `docs/validation.md`；发布前仍需真实 iPad Safari 验证。

## 用户补充资源后的判断

用户允许自行选用引擎与 Kenney 资源以减少手工代码。本原型已有 Three.js 渲染能力，且无需复杂物理、动画状态机或编辑器流水线，继续沿用比迁移完整引擎更合适。用官方 GLTFLoader、现成黄色汽车及短音效减少自制资源工作；UI 保留易触控的原生按钮。未来玩法复杂到需要物理或场景编辑器时再评估完整引擎。
