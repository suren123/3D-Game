# 有设计约束的小镇地图

`rules.generateMap(seed)` 的公共接口保持不变；逻辑目的地仍为 `place.nodeId` 对应的 `place.x/z`，`findRoute` 仍只在 4×4 正交节点上寻路。地图使用独立 `seed ^ 0x4d4150` 随机流，不消耗委托或事件随机流。

## 空间与渲染接口

世界 x/z 平面、米制，建筑正面统一为 -Z，固定镜头位于 (+X,-Z)。每个轴的节点间距为 10.5 或 11 米，车道宽 3 米，完整 Kenney 路块宽 3.75 米。地标与住宅都预留完整 6×6 米地块，不只是模型中心。模型应由 world 统一缩放到其地块；实体模型、树和标识仍需检查真实包围盒。

每个地点保留原有九个 ID、名称、图标、颜色和停靠点，新增：

```js
place.district // commercial | civic | green-fringe | logistics
place.lot = {
  x, z, width: 6, depth: 6, rotation: 0,
  entranceX, entranceZ, // 地块 -Z 正面中央，入口步道起点
  frontageX, frontageZ, // 临街边沿，比道路路块边沿外移 0.08 米
  accessEdge: [nodeA, nodeB], // 真实存在的相邻道路
  walkway: [{x, z}, ...] // 入口到街沿的正交点列，侧面访问会绕过建筑
}
```

`place.x/z` 是逻辑目的地路口（实际车辆在进入该路口前3米停在直路上），`lot.x/z` 才是建筑和庭院中心，不应混用。步道终点在路沿，不穿越车道；车辆无需驶入步道或地块。若实体门口和地块入口不同，world 可在地块内补连接段。

```js
map.layout = {
  templateId, reflectX, reflectZ,
  spacingX, spacingZ, roadWidth: 3, roadTileWidth: 3.75,
  bounds: {minX, maxX, minZ, maxZ}, // 含完整地块、道路和外围留白
  mainLoop: [nodeId, ...], // 闭环，最后节点重新接第一节点
  branchNodeId, // 唯一的外角短支路终点
  residentialLots: [/* 4 个同形状 lot，另有 id 和 residential district */],
  parkingLot, // 独立 6×6 米临街停车地块，district: parking；无法安置时为 null
  attempts, // 约束生成尝试次数，最大 512
  fallbackUsed, fallback // 两者为相同布尔值
}
```

边界的 minZ/maxZ 可以不对称，world 应按真实范围安置地台和镜头。外围景观不应越过这些边界挤占地块。

## 三类设计模板

- `village-square`：商店与餐厅沿中心街相邻，公共组围绕前方公园，中心短环保留视线和绕行。
- `garden-walk`：商业组沿花园步行街相邻，公共设施在前排，主环横向展开。
- `market-lane`：商业组在前街，公园在内街，主环纵向展开。

模板可沿 x/z 反射，但建筑朝向始终不变。商业组内可交换商店/餐厅，公共组内可交换学校/医院。农场和营地占相对的两侧外围，仓库和车库占后缘；内街区固定保留四块住宅用地。外缘地块通过侧向正交步道访问，后缘建筑朝向前方道路。

邻里停车优先使用后缘的第三块空地；若该处缺少临街道路，则选另一排的外缘地块。停车地块不取代任何住宅地块，不新增任务地点或可驾驶车辆，也不扩大边界。world 可在地块里放置 2–3 辆已预加载的静态车辆；实际车身、入口和步道仍须留出空间。

道路从模板主环、地块临街边、短支路开始，加入有约束的候选连接形成 18–20 条道路。生成器并非先随机摆地标再让 world 猜一个空位；每次返回前运行完整约束检查。最多尝试 512 次，之后使用独立于坏随机流的固定已验证 `garden-walk` 布局。

## 硬约束与验证

`validateTownLayout(map)` 返回错误说明数组。返回地图必须满足：16 个正交节点全部连通，无重复边；有完整模板主环；唯一死路是外角的一段支路，除该支路外任何一条边封闭后全部 16 节点仍连通。九个地标使用九个独立停靠点；所有 13 个必需地块与可选停车地块在边界内、互不重叠、不侵占路块或路口；每块地有真实临街道路、-Z 入口和正交步道。任务封路逻辑仍选择可恢复道路，不修改事件行为。

`tests/town-layout.test.js` 独立检查 1000 种子，包括所有地块与道路几何、商业/公共/外围分区、住宅留白、所有可封闭边、道路集合规范化后的多样性、固定种子稳定、强制 fallback 和损坏地图拒绝。三类模板的合理布局约束取代旧随机删边覆盖目标：道路拓扑按无向边排序后计数，要求 1000 种子至少 250 种真实拓扑，不能通过边数组乱序凑数。原有 1000 种子的委托、三轮完成、可恢复事件检查继续保留。

逻辑检查不等同于视觉验收。主 Agent 仍须在浏览器查看真实 GLB 的缩放、庭院内装饰、前脸可见度、遮挡、入口位置、道路观感和固定镜头构图，并完成实际驾驶与封路恢复。此模块没有进行目标 iPad 真机验收或性能优化。
