# 图片操作台升级（2026-11-14）

用户批准：右侧以图片按钮为主，物品名优先两字、最多三字；数量一件一图/一件一格，不用乘号、数字清单或分数。保留现有Babylon、3D模型/地图/镜头，只改必要交互衔接。

## 流程与规则

看任务→选车→装货→选地点→交货→完成。三个难度同流程：easy一种物品一站1–2件；normal两种物品同站各一件；challenge两种物品两站各一件、不强制顺序。停用默认突发事件；不新增复杂模式。选车最多两辆均合法且容量足够，冰激凌仅冷藏车合法时允许一辆，不虚构车型能力。货架3/4项、地点最多4项（含全部任务目标及干扰），不常驻高亮正确答案。

所有任务图、货架、货格、驾驶与交货使用相同物品图。货格最多六个，两行三列、每个64–72逻辑像素；货架图88–104。未装和已装状态清楚；装入/放回/交货从真实控件坐标转移。暂停和转屏清理动画不重复计数。数量通过重复实物图表达，阶段和完成度通过图形表达。成人模型来源信息不受儿童短标签限制。

错误地点在出发前提示并停留；地图点击和图卡走相同TRAVEL规则。已完成地点与错误地点区分；正确地点缺货不报地点错；仓库恢复始终允许。空车配送出发拒绝。到站直接换地点/回仓库，不藏帮助。行驶中移除无法兑现的换目的地入口。错货不消耗、不奖励、不改变其他格位。

## 文件责任

- picture_ui（请求GPT-6.1 Sol high）：ui.js及必要ui辅助模块，页面与图形/动画；不碰规则和主入口。
- simple_missions（请求GPT-6.1 Sol high）：rules.js/catalog.js及纯规则测试。
- 独立审查（请求GPT-6.1 Sol high）：只读最终截图/流程证据，不与实现共写。
- root：主入口/语音与有限预加载/只读测试快照/浏览器脚本/文档/最终验收发布；单GPU串行。

## 验收

先看brief/loading/explore/delivery样板，再跑三档整局与故意错站、错货、漏装、回仓库恢复。儿童页面无乘号/数字计数，物品名<=3字；触控大图可辨，格子跨阶段位置稳定。验证帮助/暂停/横竖屏/重复点击/多指/动画生命周期，准备好后断网无需新资源。构建和有意义规则测试通过，独立审查看实际图；线上部署后核对实际bundle并真实交货。云端Chromium不代表Air4真机体验。

参考：awesome-gamedev-agent-skills 的 game-ui-ux（https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/main/skills/disciplines/game-ui-ux/SKILL.md）。借鉴安全区域、缩放、层级、模态输入和页面流；不搬用其他引擎API，不额外增加手柄功能。

## 追加：手机横屏（用户2026-11-14现场反馈）

操作区锚定可用画布右侧，取消固定1180画框居中造成的右侧空白；左侧剩余面积完整交给小镇。保留系统安全区。短横屏采用独立紧凑布局，不把iPad长面板整体缩成难点的小按钮。实际验收至少844×390、667×375、844×340，交互目标至少44 CSS像素，相邻触控间距至少6，地图仍占可用画布多数宽度。可点击图片按钮有统一轮廓/按压反馈，当前建筑等静态图与只读行驶货格不能伪装成可点按钮。iPad原有72逻辑像素货格与大图布局须回归。

手机模拟不等于真实手机Safari，安全区模拟也不等于原生安装行为已验证。
