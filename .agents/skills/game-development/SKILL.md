# 游戏开发与验证

先阅读项目 [AGENTS.md](../../../AGENTS.md)、[需求记录](../../../docs/requirements.md) 和 [技术选型记录](../../../docs/technology-selection.md)。多 Agent 调度使用 [multi-agent-dev](../multi-agent-dev/SKILL.md)，此处不重复调度规则。

## 1. 先明确需求与技术边界

- 确认本次任务涉及的核心玩法、最小交付目标、平台与输入方式。未知内容保留为待确认，不自行填写帧率、设备或兼容承诺。
- 主 Agent 负责选型。研究 Agent 可以比较官方资料、版本、许可证和限制，不能各自决定技术栈或并行创建不同引擎的正式工程。
- 先在技术选型记录中形成结论，再建立实际工程。需要最小可行性实验时明确目的、范围及退出条件，并遵守用户当前对工程和依赖的限制。
- 仅在引擎确定后补充对应的引擎专用 Skill、安装命令、调试和测试流程；本 Skill 不预设引擎或框架。

## 2. 以最小可玩闭环组织开发

根据已确认玩法，优先完成进入游戏、玩家操作、核心反馈，以及适用的结束或重新开始流程。没有胜负的玩法采用其自身完成条件，不强加关卡或战斗机制。

每轮开发明确：
- 玩家能观察或操作到的变化，以及本轮不包含的内容；
- 所需模块和前置依赖；
- 可以实际验证的验收条件；
- 需要用户试玩判断的手感、视觉或趣味性问题。

先完成可运行的小闭环，再扩展场景和内容。不以代码文件数量或角色数量衡量完成度。

## 3. 并行开发前的接口约定

只为本轮涉及的模块定义最小接口，例如输入、角色控制、相机、场景、游戏状态和 UI，不要求一开始建立全部模块。

约定调用或事件关系、状态所有权、初始化与销毁顺序；涉及空间和时间时明确坐标、单位及更新时序。主 Agent 负责共享入口和最终集成，模块 Agent 在自己的文件范围内实现。

接口变更先反馈主 Agent，并通知依赖方；不能各模块各自猜测接口。先消除依赖，再安排并行实现。资源需求出现时记录来源、许可证与体积，不因本 Skill 预建资源目录或下载无关素材。

## 4. 区分构建、运行与试玩验证

从实际工程配置识别检查命令，不编造尚不存在的测试。对游戏行为的修改，按影响范围执行：

| 层次 | 验证内容 |
| --- | --- |
| 静态与构建 | 已配置的类型、静态检查、相关测试和构建 |
| 浏览器运行 | 页面启动、实际画面、控制台异常、网络失败与资源加载 |
| 交互流程 | 已支持的输入、核心行为、状态切换，以及适用的结束或重启 |
| 回归与边界 | 与改动有关的失焦/恢复、窗口变化、重复进入退出和资源清理 |

- 必须实际启动并使用浏览器工具、自动化或可复现的人工试玩验证游戏改动；构建通过不能标记“游戏可玩”。
- 对 Canvas / WebGL 游戏，不能只检查 DOM 或页面加载成功。结合实际输入、渲染画面与可观察的游戏状态验证行为；需要测试接口时保持最小范围，不向产品流程泄露调试信息。
- 截图只能证明特定画面，不能单独证明操作、碰撞、动画时序或性能。按需保留短录像、日志或复现步骤。
- 浏览器或图形能力失败时先诊断具体原因，完成能做的检查并报告阻断；未执行的试玩不得写成通过。一般文档修改无需运行游戏。
- 操作手感、视觉效果和趣味性需要用户反馈；代理验证与用户实际试玩反馈分别记录。

## 5. 3D模型与地图的视觉验收门槛

- 模型加载、哈希、来源和图鉴功能通过，只能证明资源可用，不能证明组合外观正确。组合模型逐件查看可辨细节的实际渲染，保留同角度修正前后图，再检查放回小镇后的比例和遮挡。
- 检查附加标识的完整支撑链、屋顶接点、雨棚与墙面、入口与庭院。用实际三角形/屋面定位验证疑似悬空或穿插，不能以整栋楼包围盒最高点替代标识下方的真实屋面。既不凭存在一个“支柱”名称判通过，也不把投影重叠直接写成实际碰撞。
- 不只看文件名选择朝向：实际查看源模型的入口、正面和细节。对帐篷等组合场景，确认主视角能够读到入口，附属树木和道具不堵入口或穿进主体。
- 道路逐类检查弯道、T口、十字与尽端近景。坐标转换以引擎实际加载的节点矩阵为依据，避免实现与测试重复同一个错误反射假设。
- 车辆检查包含完整车身沿弯道扫掠、到达停稳和再次出发，不能只检查车中心在道路上。起步调头等尚未覆盖的动作必须单列限制，不扩展为全碰撞验收通过。
- 全镇图、驾驶近景、模型图鉴与侧栏都要实际查看。文字和点击区域不能遮挡建筑或互相侵占；缩略图必须在真实显示尺寸下有辨识作用。独立审查列具体图、位置、问题与复验结果；未看、待测或仅几何通过的部分保持未验收。

## 6. 性能与兼容性

仅对本轮涉及的性能或兼容目标测量，数值阈值来自已确认需求。目标未定时报告测量值与条件，不擅自宣称达标。

记录版本或提交、测试场景、浏览器及版本、设备或云端配置、渲染后端与是否软件渲染、分辨率/像素比、测量方法及时间窗口。需要时区分冷加载与热加载，测量帧时间、加载耗时、内存或资源体积。

云端渲染结果不能直接代表玩家设备。未在目标设备或浏览器上验证的部分明确列为未验证，不承诺兼容或帧率。

## 7. 验收报告

主 Agent 汇总：已实现的玩家行为、实际测试版本与环境、检查命令及结果、浏览器交互证据、已知问题和待用户试玩项。按已确认的验收条件判断完成度；修复后重新验证受影响行为。
